## Phase Goal

> ROADMAP Phase 3 Goal (verbatim, not a user story; no story is invented, MVP framing would need `/gsd-mvp-phase 03`): "We can call each other by voice or video, peer-to-peer with Cloudflare TURN relay, on Wi-Fi or cellular, with push-to-answer ringing"

This plan delivers ROADMAP success criterion 1 for voice (start a call from the chat, both hear each other) and the in-app half of criterion 2 (incoming screen with Accept and Decline, 45 s timeout, cancel while ringing). Push ringing follows in 03-02, video and in-call controls in 03-03, reconnect and the device UAT in 03-04.

<objective>
Let either person start a voice call from the chat header that rings the other person's open app, connects peer-to-peer through Cloudflare TURN when accepted, and ends cleanly in every way a call can end: hang up, cancel, decline, 45 s no answer, setup failure, a vanished party, a second device answering, both calling at once, or a call while already in one.

Purpose: the core call path (CALL-01) and its ringing lifecycle (CALL-04), built on the architecture every later slice extends: server call registry, call.* frames on the existing /ws, fixed-role perfect negotiation with pre-negotiated audio+video transceivers, and an app-level call layer above the chat.
Output: shared call contract, server registry + hub wiring + tests, client call store/session/tones, call/incoming screens, permission drawer, header voice button, smoke-calls E2E.
</objective>
