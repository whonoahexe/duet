## Phase Goal

> ROADMAP Phase 2 Goal (verbatim, not a user story; no story is invented): "We can message each other in real time, reliably, with history kept forever, share photos, short video clips and voice notes that display and play correctly on both an iPhone and a Pixel (visible only to the two of us), and get a push notification when the app is not open"

This plan delivers the photo half of ROADMAP success criterion 4 (camera or library photos, iPhone HEIC on the Pixel, tap to view full screen) and the access/Range part of criterion 5, and deploys everything built so far (02-01..02-04).

<objective>
Let either person pick photos (camera or library), preview them with a caption, and send up to 10 as one album that renders as a grid on both phones, including iPhone HEIC, with a swipeable full-screen viewer; serve media only to the two logged-in users with Range support; build the shared upload and processing pipeline that 02-05 extends with video and voice; ship it to production with the container toolchain verified.

Purpose: MDIA-01, MDIA-02, MDIA-05 and decisions D-05, D-06, D-07, D-09.
Output: chunked upload routes, image processing lane, auth-gated media route, album/preview/viewer UI, container toolchain, tests, e2e scenarios, deploy.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `/api/uploads*` | Untrusted bytes, sizes and indexes from a logged-in client |
| uploaded file -> sharp / heif-convert child process | Attacker-shaped image data reaches native decoders |
| browser -> `GET /media/:id/:variant` | Path parameters choose files on disk |
| server -> Cloudflare edge | Private media crosses the CDN |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-21 | Information disclosure | GET /media | high | mitigate | requireUser preHandler; 128-bit random ids; ready-only; tests for 401/404 |
| T-02-22 | Tampering (stored XSS) | serving uploaded bytes | high | mitigate | the original is never served; only sharp-regenerated variants with fixed Content-Types from the VARIANTS map; global nosniff |
| T-02-23 | Tampering (path traversal) | media/uploads paths | high | mitigate | ids must match ^[A-Za-z0-9_-]{22}$, variants come from a fixed map, every path is server-built under the media root |
| T-02-24 | Denial of service | chunk uploads | medium | mitigate | requireUser in onRequest before the body is parsed; 8 MiB bodyLimit; exact chunk lengths; declared-size caps; 24 h temp cleanup |
| T-02-25 | Denial of service | decompression bombs | medium | mitigate | sharp's default limitInputPixels; 100 MB image cap; one image job at a time in the fast lane |
| T-02-26 | Information disclosure | photo EXIF/GPS | high | mitigate | display and thumb are written without metadata (test asserts no EXIF); the original stays on disk only |
| T-02-27 | Information disclosure | edge caching of media | medium | mitigate | extensionless URLs, Cache-Control private on ready files, no-store on 404s; smoke-public checks cf-cache-status |
| T-02-28 | Elevation of privilege | attaching uploads | medium | mitigate | uploader must equal the sender and message_seq must be NULL inside the send transaction (400 bad_attachment) |
| T-02-29 | Tampering (command injection) | heif-convert/ffmpeg spawns | high | mitigate | runTool uses argument arrays, no shell, server-built paths, timeouts and bounded stderr |
| T-02-SC | Tampering | npm installs (sharp, embla-carousel-react) | high | mitigate | sharp installed only after the blocking-human approval recorded by 02-03 Task 3 (precondition); embla passed the audit; exact pin for sharp |
