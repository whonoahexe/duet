# Phase 03 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Sources: `03-CONTEXT.md` (D-01..D-21 and the discretion list), `02-UI-SPEC.md` (approved chat-shell contract: tokens, type scale, header, toast), `02-UI-REVIEW.md` (lessons: declare every exception, keep exactly 4 sizes), `.claude/CLAUDE.md` (locked preset), and the live codebase (`web/components.json`, `web/app/globals.css`, `web/components/app/shell.tsx`, `web/components/app/viewer.tsx`, `web/components/ui/*`, `web/lib/rtc/*`). This phase has no RESEARCH.md. No questions were needed: CONTEXT.md and the codebase answer every contract question. Values chosen under "Claude's Discretion" are marked **(default)**.

**Hard rule (carried from Phase 2):** every component comes from `npx shadcn add <name>` (run in `web/`) with the `base-luma` style. Icons come only from `@phosphor-icons/react`. Colors come only from the preset CSS variables in `web/app/globals.css` through Tailwind token classes (`bg-destructive`, `text-background`, `bg-background/60`, …). No new CSS variables, palettes, fonts, lucide, Radix, emoji-picker or call-UI libraries. Editing `globals.css` tokens is not allowed. Utility classes on top of preset components are allowed.

## Spacing Scale

Declared values (all multiples of 4, Tailwind units in brackets). Same scale as Phase 2.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`1`) | Icon-to-text gap inside the Poor connection badge, gap between name and status line |
| sm | 8px (`2`) | Gap between a round Accept/Decline button and its label, on-call bar icon-to-text gap, control gap on viewports narrower than 380px |
| md | 16px (`4`) | Gap between in-call control buttons, on-call bar horizontal padding, control pill horizontal padding, PiP inset from the screen edges and from the control pill |
| lg | 24px (`6`) | Gap between the avatar and the name block, call-screen horizontal padding (`px-6`), minimum bottom padding under the control pill |
| xl | 32px (`8`) | Gap between the end-state message and its action buttons |
| 2xl | 48px (`12`) | Gap between the Decline and Accept buttons on the incoming screen |
| 3xl | 64px (`16`) | Top padding of the centered avatar block below the top bar; Accept/Decline button size |

Layout rules:
- Call screen top bar: `h-14` (56px) plus `pt-[env(safe-area-inset-top)]`, `px-4`, matching the chat header height.
- Control pill: pinned bottom center, `mb-[max(24px,env(safe-area-inset-bottom))]`, `rounded-4xl bg-background/60 backdrop-blur-md px-4 py-4`, buttons in a row with `gap-4` (`max-[379px]:gap-2`).
- Incoming screen: Decline and Accept sit in one row, `gap-12`, at the same bottom offset as the control pill.
- On-call bar: `h-11` (44px), full width, mounted directly under the chat header (above the notifications card), `px-4`.

Exceptions:
- **In-call control buttons are 56px** (`size-14`, round): larger than the 44px minimum because they are hit while holding the phone at arm's length. Accept/Decline are 64px (`size-16`), on the scale.
- **Self-view PiP is 96×128px** (`w-24 h-32`, 3:4 portrait, `rounded-2xl`), a media dimension, not layout spacing. It snaps to the nearest of the four corners, inset 16px from the safe area; bottom corners also clear the control pill by 16px while the controls are visible.
- **Header `gap-3` (12px)** is inherited from Phase 1 (same exception as Phase 2). The two new header icon buttons use the preset `size="icon"` (36px), like the existing menu button.
- **Drag thresholds** are gesture distances: movement under 8px counts as a tap on the PiP (swap); 8px or more is a drag.
- Preset component internals (button heights, avatar ring, badge padding, drawer padding) are used unchanged.

## Color

Preset dark tokens from `web/app/globals.css` `.dark`. Use token classes, never hex.

| Role | Token | Value (≈hex) | Usage |
|------|-------|--------------|-------|
| Dominant (60%) | `--background` | oklch(0.148 0.004 228.8) ≈ #090b0c | Call screen and incoming screen background, top bar, control pill (`bg-background/60` over video) |
| Secondary (30%) | `--secondary` / `--muted` | oklch(0.274 0.006 286.033) ≈ #27272a / oklch(0.275 0.011 216.9) ≈ #22292b | In-call control buttons (`variant="secondary"`), avatar fallback (`bg-muted`), PiP placeholder while the camera warms up (`bg-muted`), Poor connection badge, drawer surface (`--popover`) |
| Accent (10%) | `--primary` | oklch(0.455 0.188 13.697) ≈ #a50036 (text `--primary-foreground` ≈ #fff1f2) | Only the elements listed below |
| Text | `--foreground` / `--muted-foreground` | ≈ #f9fbfb / ≈ #9ca8ab | Peer name, control glyphs / status line, timer, Accept/Decline labels |
| Destructive | `--destructive` | oklch(0.704 0.191 22.216) ≈ #ff6467 | Hang up and Decline only |

Accent (`--primary`, solid) is reserved for:
1. The **Accept** button on the incoming-call screen (`variant="default"`, round 64px).
2. The **on-call bar** at the top of the chat (`bg-primary text-primary-foreground`), so a minimized call is impossible to miss.
3. The single primary action of a terminal call state: **Call back** ("Call dropped"), **Retry** ("Couldn't connect"). These states replace the control pill, so there is never more than one accent control on the call screen.

Do not use accent for: the header call icons (`ghost`), in-call toggles, the minimize button, the Poor connection badge, the timer or status line, or toast actions (preset sonner styling).

**Pressed (on) state of in-call toggles** uses an inversion of existing tokens, not accent: `aria-pressed="true"` → `bg-foreground text-background hover:bg-foreground/90`. Off → preset `secondary`. Contrast of `--background` on `--foreground` is above 15:1.

Destructive is used only for:
- **Hang up** (in-call pill) and **Decline** (incoming screen): `variant="destructive"` plus the solid override `bg-destructive text-background hover:bg-destructive/80`. The glyph is `text-background` (≈#090b0c on ≈#ff6467, about 6.8:1); white would fail the 3:1 graphics minimum (about 2.9:1). Hang up never asks for confirmation (no data is lost).

## Screens and Interaction Contract

The call state lives in an app-level `CallProvider` mounted in `Shell` (above `ChatView`, D-06). The provider renders the call `Dialog`, the incoming `Dialog` and exposes state to the header and the on-call bar. Only one call surface is open at a time.

### 1. Chat header: start a call (D-01)

- Two new `Button variant="ghost" size="icon"` buttons between the name block and the existing menu, in this order: `PhoneIcon` (`aria-label="Voice call"`), `VideoCameraIcon` (`aria-label="Video call"`). One tap starts the call and opens the call screen immediately in the Ringing state.
- Hidden when there is no peer account ("Waiting for your person").
- Disabled (preset `disabled:opacity-50`) while a call is active or ringing on this device; the on-call bar is the way back.
- Tapped while the WS connection is down (`connection !== "live"`): no call starts; toast "You're offline. Calls need a connection."
- Starting a call requests the microphone (and the camera for a video call) inside the tap gesture, so iOS can play the ringback.

### 2. Call screen: one screen for voice and video (D-02, D-03, D-04)

Full-screen `Dialog`. Two visual modes chosen only by whether **remote video** is present.

**Mode A: no remote video** (voice call, ringing, connecting, or the remote camera is off)
- Top bar (`h-14`): `CaretDownIcon` ghost icon button left, `aria-label="Back to chat"`; the Poor connection badge right when shown.
- Centered block, `pt-16`, `flex-col items-center`: Avatar 96px (`size-24`, initials 20px) → 24px → peer name (20px medium, `truncate max-w-full`) → 4px → status line (14px, `text-muted-foreground`, `tabular-nums`).
- **Primary anchor:** the avatar + name block; the eye lands on who you are talking to, then on the status line. The control pill is secondary; Hang up is the only saturated control in it.
- If the local camera is on (an outgoing video call while ringing, or you turned your camera on in a voice call), the self-view PiP shows in its corner. The center stays the avatar.

**Mode B: remote video present**
- Remote `<video autoplay playsInline>` fills the screen (`absolute inset-0 size-full object-cover`). The remote audio is a separate always-mounted `<audio>` element so minimizing never stops audio.
- Top bar overlays the video with `bg-background/60 backdrop-blur-md`: Back to chat (left), then the name (14px medium, truncate) and the timer (12px, `tabular-nums`, muted) stacked; the Poor connection badge right.
- **Primary anchor:** the remote video. The top bar and control pill are translucent and auto-hide.
- Self-view PiP: `w-24 h-32 rounded-2xl overflow-hidden object-cover`, `ring-1 ring-border`, front camera mirrored (`-scale-x-100`), back camera not mirrored. Hidden while the local camera is off.
  - **Drag** (8px or more): follows the finger, on release snaps to the nearest corner in 200ms (instant under reduced motion). Corner position is remembered for the rest of the call **(default)**.
  - **Tap** (under 8px): swaps the large and small views. The swapped state shows the self-view full-screen and the remote video in the PiP. Swapping again restores it. If either video stops, the swap resets.
  - The PiP is a `button` with `aria-label="Swap videos"`.
- **Auto-hide (D-02, default timing):** in Mode B only, the top bar and control pill fade out (200ms opacity) 4 seconds after the last tap or control press. A tap anywhere on the remote video toggles them back. While hidden they are `inert`. They never auto-hide in Mode A, while a status other than the timer is showing (Connecting…, Reconnecting…, Poor connection), or while the screen-reader / keyboard focus is inside them.

**Status line content** (one value at a time, highest first):
1. Terminal states (section 5)
2. "Reconnecting…" (D-17)
3. "Ringing…" (caller, until accepted)
4. "Connecting…" (after accept until media flows)
5. The running timer "m:ss", "h:mm:ss" past an hour, counted from the moment media first flows on both sides

"Poor connection" is not a status-line value; it is the badge (section 6), so it can coexist with the timer.

**Control pill** (D-04), left to right; every button `size-14 rounded-full`, icons `size-6`:

| Control | Shown | Type | aria-label | Pressed when |
|---------|-------|------|------------|--------------|
| Mute (`MicrophoneSlashIcon`) | always | toggle, `aria-pressed` | Mute | mic is muted |
| Camera (`VideoCameraIcon`) | always | toggle, `aria-pressed` | Camera | your camera is on |
| Flip (`CameraRotateIcon`) | only while your camera is on | action, `secondary` | Switch camera | — |
| Speaker (`SpeakerHighIcon`) | only where output switching works (D-05: `setSinkId` / `selectAudioOutput` present; hidden on iOS) | toggle, `aria-pressed` | Speaker | speaker output is active |
| Hang up (`PhoneDisconnectIcon`) | always | action, solid destructive | Hang up (while ringing as caller: Cancel call) | — |

- Speaker default (D-05): on for a call that started as video, off (earpiece) for voice, where the OS honours it.
- Turning the camera on in a voice call renegotiates (D-03); the PiP appears once the first frame arrives. The other side switches from Mode A to Mode B when the remote track starts and back when it stops or is muted.
- Flip switches between front and back camera with `replaceTrack`; the PiP shows the new stream and updates the mirroring.

### 3. Incoming-call screen (CALL-03, D-08, D-09, D-11)

Full-screen `Dialog`, opened when a `call.ring` arrives on this device, when the app is opened from the incoming push, or when the app is opened while a call is ringing.
- Centered block identical to Mode A: avatar 96px → name (20px) → status "Incoming voice call" / "Incoming video call" (14px muted).
- Bottom row (`gap-12`, centered): **Decline** (left) and **Accept** (right), each a 64px round button with a 14px medium label 8px below it.
  - Decline: solid destructive, `PhoneDisconnectIcon`, `aria-label="Decline"`, label "Decline".
  - Accept: `variant="default"` (accent), `PhoneIcon` for voice or `VideoCameraIcon` for video, `aria-label="Accept"`, label "Accept". On tap it shows `Spinner` in place of the icon and is disabled until the call screen takes over.
- **Primary anchor:** the Accept button (the only accent on screen), with the name block above it as context.
- Accepting a video call turns your camera on; accepting a voice call keeps it off (D-03).
- While ringing in the foreground (D-08): a looping ringtone generated with WebAudio **(default)**, and `navigator.vibrate?.([800, 400])` repeating where supported. If audio is blocked before a user gesture (iOS), the screen shows silently. There is no Escape/Back dismissal; only Decline, Accept, caller cancel, timeout, or "answered elsewhere" close it.
- When another of your devices answers or declines first (D-11), this screen closes, the ringing stops, and a toast says "Answered on another device" (accepted elsewhere only; declined elsewhere is silent).

**Caller side while ringing:** the call screen in Mode A with status "Ringing…", ringback tone looping (WebAudio, **default**), and the full control pill (Hang up reads `aria-label="Cancel call"`).

### 4. Minimized call: on-call bar (D-06)

- "Back to chat" (or Escape / the dialog closing) hides the call screen. The call, audio, camera and timer continue.
- A full-width `button` (`h-11`, `bg-primary text-primary-foreground`, `px-4`, `text-sm font-medium`) appears directly under the chat header: `PhoneIcon` (fill, `size-4`) · "On call · 2:14" (timer in `tabular-nums`) · flex spacer · `CaretRightIcon`. During reconnect it reads "Reconnecting…"; while the caller is ringing it reads "Ringing…". `aria-label="Return to call"`.
- Tapping it reopens the call screen in its previous mode and swap state.
- The bar is not shown while the call screen is open, and it disappears when the call ends (no end-state animation on the bar; the end state is shown on the call screen only if it is open, otherwise a toast, see section 5).

### 5. Terminal states (D-07, D-13, D-15, D-16, D-17, D-19)

| State | When | What the user sees | Then |
|-------|------|--------------------|------|
| Declined | callee declined | Mode A, status "Declined", control pill hidden | Back to chat after 2 s |
| No answer | 45 s server timeout (also when the callee has no device, D-16) | Mode A, status "No answer", pill hidden | Back to chat after 2 s **(default, same as Declined)** |
| Call ended | either side hangs up after connecting | Mode A, status "Call ended · m:ss", pill hidden | Back to chat after 1.5 s |
| Cancelled (callee side) | caller cancels while ringing | Incoming screen closes | Missed-call push replaces the incoming one (D-12); no toast if the app is open, since the user saw it ring |
| Call dropped | reconnect gave up after 30 s (D-17) | Mode A, `WarningCircleIcon` (`text-muted-foreground`) above title "Call dropped" (20px), 32px, then **Call back** (`default`, accent) and **Close** (`ghost`) stacked full-width in `max-w-xs` | Stays until a button is tapped |
| Couldn't connect | ICE failed before media ever flowed, or setup errored | Same layout: title "Couldn't connect", body "Check your connection and try again." (16px muted), **Retry** (accent) + **Close** (ghost) | Stays until a button is tapped |

- Call back and Retry start a new call of the same kind (voice/video) to the peer.
- If a call ends while minimized, no call screen reopens; Declined / No answer / Call ended show as a toast with the same copy, Call dropped / Couldn't connect show as a toast with a Call back / Retry action.

### 6. Reconnect and quality (D-17, D-20)

- **Reconnecting:** ICE `disconnected`/`failed` or WS loss switches the status line (and on-call bar) to "Reconnecting…". Video freezes on its last frame; nothing else changes. Controls stay visible and usable. When media flows again, the timer returns (it never reset). After 30 s → "Call dropped".
- **Poor connection badge (default thresholds):** sample `getStats` every 2 s (reuse `web/lib/rtc/stats.ts`, extended with inbound packet loss). Show the badge when 2 consecutive samples have inbound packet loss above 5% or RTT above 400 ms; hide it after 3 consecutive good samples. `Badge variant="secondary"` with `WifiLowIcon` + "Poor connection", in the top bar's right slot. Hidden during Reconnecting (the status line already says it). Announced once per appearance through the call screen's `aria-live="polite"` region.

### 7. Stale push, missed calls and tips (D-10, D-12, D-18)

- Opening the app from an incoming-call push for a call that has already ended: land on the chat, toast "Missed call from {peer}" with action "Call back" (starts a call of the same kind). Nothing is stored.
- **iOS one-time tip:** on the first connected call on an iOS device (flag in `localStorage`), toast "Keep duet open during calls" with description "On iPhone, video pauses when duet is in the background." (duration 6 s). Never shown again on that device.
- Screen wake lock (D-21) has no visual. If the Wake Lock API is missing, do nothing visible **(default)**.

### 8. Permissions (D-19)

- **Microphone denied** (any call, outgoing or accepting): the call does not start (or is declined on the callee side with the callee's screen closed); the chat shows the permission `Drawer`: title "Allow the microphone" (20px), body (16px) with the platform steps from the Copywriting Contract, and a full-width "Close" (`outline`) button in `DrawerFooter`. No accent in the drawer, since there is nothing to retry until settings change.
- **Camera denied** (starting a video call, accepting one, or turning the camera on): the call continues audio-only, the Camera toggle stays unpressed, and a toast "duet can't use the camera." with an action "How to allow" opens the same Drawer with the camera title and steps.

### 9. Push notification content (D-09, D-12)

| Push | Title | Body | Tap |
|------|-------|------|-----|
| Incoming voice call | {peer} | 📞 Incoming voice call | Opens/focuses duet on the incoming-call screen for that call id (or the stale-push toast) |
| Incoming video call | {peer} | 🎥 Incoming video call | same |
| Missed (replaces incoming, D-12) | {peer} | 📞 Missed voice call / 🎥 Missed video call | Opens/focuses duet on the chat with the "Missed call from {peer}" toast and Call back |

The SW closes any open duet notification before showing a call push (iOS ignores `tag`), so an incoming-call push replaces a chat notification and the missed push replaces the incoming one. TTL ≈45 s and high urgency for incoming; the missed push uses the normal message TTL.

## Accessibility and Motion

- Every icon-only control has the `aria-label` listed above; toggles use `aria-pressed`.
- The call `Dialog` has `DialogTitle className="sr-only"`: "Call with {peer}" / "Incoming call from {peer}".
- One visually hidden `aria-live="polite"` region on the call screen announces status changes (Ringing…, Connecting…, Connected, Reconnecting…, Poor connection, terminal states). The running timer itself is not live (`aria-live="off"`), so it is not read every second.
- Auto-hidden controls are `inert` and come back on any tap, any key press, or focus entering the pill.
- `prefers-reduced-motion`: no control fade (show/hide instantly), PiP snaps without animation.
- Focus rings come from the preset; do not remove them on the round control buttons.
- Remote and self videos are `muted` on the `<video>` elements (audio goes through the separate `<audio>`), which also satisfies iOS inline autoplay.
