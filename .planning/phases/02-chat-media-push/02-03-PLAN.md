## Phase Goal

> ROADMAP Phase 2 Goal (verbatim, not a user story; no story is invented): "We can message each other in real time, reliably, with history kept forever, share photos, short video clips and voice notes that display and play correctly on both an iPhone and a Pixel (visible only to the two of us), and get a push notification when the app is not open"

This plan delivers ROADMAP success criterion 3: push when the app is closed on both phones, tapping opens the chat, no push while viewing, and first-run iPhone onboarding with a real test push. It also holds the package-legitimacy gate for sharp, which plan 02-04 installs.

<objective>
Push a notification for every new message to the other person when they are not viewing the chat (NOTF-01, NOTF-03), with the sender's name and message text, collapsed into one notification (D-13, D-14), opening the chat on tap (NOTF-02). Guide iPhone users to install duet and turn on notifications with a test push, on both phones until done (SHEL-03, D-16). Then stop for the owner to approve sharp before plan 02-04 installs it.

Purpose: messages are useless if the other person doesn't know they arrived; iOS only allows web push for installed apps, so onboarding is part of the feature.
Output: VAPID script, push sender/routes/listener, service worker handlers, client push module, onboarding guide, card and drawer, tests and an onboarding e2e, and the sharp approval.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> `POST /api/push/subscriptions` | A logged-in client hands the server a URL the server will later POST to |
| duet server -> push services (Apple, FCM) | Encrypted payloads with message previews leave the server, signed with the VAPID private key |
| push service -> service worker | Payload arrives on the lock screen of a possibly logged-out device |
| operator host -> repo env file | deploy/vapid-keys.sh writes the VAPID private key |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-14 | Information disclosure / SSRF | subscription endpoint | high | mitigate | https only, host allowlist (FCM, *.push.apple.com, Mozilla, *.notify.windows.com) via isAllowedPushEndpoint, length <= 2048; tests reject 127.0.0.1 and other hosts |
| T-02-15 | Information disclosure | lock-screen previews after logout | high | mitigate | push_subscriptions.session_id ON DELETE CASCADE; logout deletes the session; test proves no push after logout |
| T-02-16 | Information disclosure | VAPID private key | high | mitigate | lives only in the gitignored env file written atomically under umask 077; never printed or logged; push logs carry code + host only |
