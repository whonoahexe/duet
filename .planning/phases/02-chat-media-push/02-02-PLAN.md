## Phase Goal

> ROADMAP Phase 2 Goal (verbatim, not a user story; no story is invented): "We can message each other in real time, reliably, with history kept forever, share photos, short video clips and voice notes that display and play correctly on both an iPhone and a Pixel (visible only to the two of us), and get a push notification when the app is not open"

This plan adds what makes the chat feel like the couple's own messenger: reactions from their personal set, swipe-to-reply quotes, the typing indicator and iMessage-style read receipts (ROADMAP success criterion 1).

<objective>
Let each person react to any message with one of the six fixed emoji (D-04), reply to a specific message by swiping right or from the long-press menu and see it as a quote that jumps to the original (D-01, D-02), see when the other person is typing (CHAT-06), and see "Read 9:41" under their latest message once it has actually been seen (CHAT-07, D-03).

Purpose: CHAT-06..09. Every feature is a full vertical slice: shared contract, server route or hub frame, store, gesture/UI, and a headless two-browser scenario.
Output: reaction and read routes, reply validation and previews, typing relay, gesture hooks, popover menu, quote block, typing indicator, read tracker, and three new e2e scenarios.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-09 | Spoofing | reaction / read routes | high | mitigate | the reacting or reading user is always request.user.id; bodies carry no user id (strict schemas); tests assert bob's PUT never changes alice's reaction |
| T-02-10 | Tampering | reaction emoji | medium | mitigate | REACTIONS allowlist on write (exact string equality); seq param validated as a positive integer; 400 otherwise |
| T-02-11 | Information disclosure | read receipts | medium | mitigate | receipts only when visible + focused + on screen (Pitfall 14); one cursor per user, never per-message tracking |
| T-02-12 | Denial of service | typing frames | low | accept | client throttle 3 s plus the existing 100 frames/s per connection cap; relay goes only to the other user's sockets |
| T-02-13 | Tampering | replyToSeq | low | mitigate | parent must exist inside the send transaction (400 bad_reply); previews are server-built and grapheme-truncated |
| T-02-SC | Tampering | npm/pip/cargo installs | high | mitigate | this plan installs nothing and runs no `shadcn add` (popover came from 02-01); the sharp gate lives in 02-03 Task 3 |
