Add WebAudio-synthesised sound effects to duet: message sent pop, received chime (throttled), reaction tick, voice-note record start/stop clicks, call connected / ended / dropped, reminder chime and missed-call sound. They reuse the existing AudioContext and unlockAudio from web/lib/call/tones.ts, and there are no asset files. The plan also groups the ⋮ header menu and the + attach menu into labelled sections, and moves the sound-effects todo to completed.

Locked user decisions (from the request; they override the todo text):
- U-01: there is NO Sounds on/off toggle. Sounds are always on, with no switch anywhere, no menu item and no stored preference. The todo's suggested ⋮-menu toggle is dropped.
- U-02: both menus use only the locked preset's (base-luma, Base UI) menu parts: DropdownMenuGroup, DropdownMenuLabel and DropdownMenuSeparator, which are already installed in web/components/ui/dropdown-menu.tsx. No hand-rolled markup and no Radix.

From the note (decided earlier): the sounds are synthesised in code with no asset files or licences, and they reuse the tones.ts context instead of a second one. Known limits, written down and not fixed: the iPhone silent switch mutes web audio; nothing plays while duet is closed (push uses the OS sound); and nothing plays before the first tap of a session.

Purpose: duet feels alive. Sending, receiving, reacting, recording and call state changes get audible feedback on both phones.
Output: web/lib/sounds.ts plus wiring in the chat store, realtime, call store and recorder; grouped menus in shell.tsx and composer.tsx; smoke coverage in scripts/smoke-chat.mjs and scripts/smoke-calls.mjs; the todo moved to completed.
