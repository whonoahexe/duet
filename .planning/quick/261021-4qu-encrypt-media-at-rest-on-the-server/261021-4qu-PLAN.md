1. server/src/media/crypto.ts (new; it imports nothing from other media modules so it can never form an import cycle). Format choices, recorded here because they are mine to make:
   - Header, ENC_HEADER_LEN = 36 bytes: bytes 0-6 are ASCII "DUETENC"; byte 7 is version 0x01; bytes 8-11 are the chunk size as u32 BE (ENC_CHUNK = 65536); bytes 12-19 are the plaintext size as u64 BE; bytes 20-35 are 16 random bytes of file id.
   - Chunks: chunk i (0-based, count = ceil(plainSize / ENC_CHUNK), zero chunks for an empty file) starts at offset ENC_HEADER_LEN + i * (ENC_CHUNK + 28). Each chunk is a 12-byte random nonce, then the ciphertext (ENC_CHUNK bytes; the last chunk is shorter), then the 16-byte GCM tag. The AAD of chunk i is the full 36-byte header followed by i as u32 BE. Because the header carries the size and file id, a chunk cannot be reordered, swapped between files or truncated without detection.
   - Exports:
     - encryptedSize(plainSize).
     - encryptBuffer(key, plain): Buffer.
     - encryptFile(key, srcPath, dstPath): stat src, read it ENC_CHUNK at a time through a FileHandle (loop until each chunk is full), write to "<dst>.<8 hex>.tmp" in dst's dir, rename it over dst, and rm the temp on any error.
     - readEncHeader(filePath): returns { plainSize, etag (the 32-hex file id), raw (the 36 header bytes) } or null when the magic, version or chunk size is wrong, the size exceeds MAX_SAFE_INTEGER, or the stat size is not encryptedSize(plainSize). ENOENT propagates.
     - decryptChunks(key, filePath, header, start, endInclusive): an async generator. It opens the file once, reads only chunks floor(start / ENC_CHUNK) through floor(end / ENC_CHUNK), decrypts each with setAAD + setAuthTag + final (a bad tag throws), yields the sliced plaintext, and closes the handle in finally.
     - decryptToFile(key, src, dst): pipe the full decryptChunks into a write stream; an empty plaintext gives an empty file.
     - readDecrypted(key, file): Buffer, for tests and small parts.
     - sha256Decrypted(key, file): hex.
     - readMediaKey(keyFile): read, trim, strict base64 decode to exactly 32 bytes (re-encoding must equal the trimmed text). Missing or malformed throws MediaKeyError with the path and the reason. It never writes.
     - loadMediaKey({ keyFile, mediaRoot }): returns { key, created, loosePermissions } (loosePermissions = mode & 0o077 is non-zero). On ENOENT it first walks mediaRoot recursively (readdir with recursive and withFileTypes). If any regular file there has a valid header, it throws MediaKeyError ("<keyFile> is missing but <mediaRoot> already holds encrypted media; restore the key from your backup, a new key cannot read it"). Otherwise it does mkdir(dirname, recursive, mode 0o700) and writeFile(base64 of randomBytes(32) plus a newline, flag "wx", mode 0o600). It never overwrites: on EEXIST it re-reads. Every other error (EISDIR, EACCES, ...) becomes a MediaKeyError naming the path.
     - class MediaKeyError (name "MediaKeyError").
   - The key value is never logged or included in an error.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-4qu-01 | Information disclosure | data/media files | high | mitigate | AES-256-GCM on every stored file: variants (Task 1), originals and parts (Task 2), and existing files through the boot migration. Plaintext lives only in media/work scratch, removed in finally blocks and wiped at boot. media-check proves there is no plaintext left. |
| T-4qu-02 | Information disclosure | ~/.config/duet/media.key | medium | accept | Decided 2026-10-20 (level 1): the goal is only to stop casual browsing. Anyone who reads the 0600 key with the same login, or root, can decrypt. That is documented in the README and out of scope. |
| T-4qu-03 | Tampering | ciphertext chunks | medium | mitigate | A GCM tag on every chunk. The AAD (header with size and file id, plus the chunk index) blocks reordering, cross-file swaps and truncation. A size mismatch makes the header invalid, so the route returns 500 and never serves garbage. Tests flip and swap chunks. |
| T-4qu-04 | Denial of service (data loss) | key handling | high | mitigate | The key is written with flag wx, so it is never overwritten. The server refuses to boot or create a key when encrypted media exists. The container cannot create a key (ENV path under root-owned /run, read-only mount, create_host_path false). There is a loud media_key created log, and the README and SUMMARY tell the owner to back the key up. |
| T-4qu-05 | Denial of service | parseRange / decryptChunks | low | mitigate | Only a single bytes= range is honored. Malformed or multiple ranges are ignored (full 200). Out-of-range requests get a 416. Bounds are clamped to the plaintext size, only the covered chunks are read, and HEAD never decrypts. |
| T-4qu-06 | Information disclosure | logs and errors | medium | mitigate | Logs and MediaKeyError messages carry only the key path, counts and relative media paths, never the key. The scripts never print the key. |
| T-4qu-07 | Tampering (data loss) | boot migration | high | mitigate | Each file is encrypted to a temp file, the decrypted sha256 is checked against the plaintext, and only then is the temp renamed over the file. Per-file failures are logged and the file is skipped (the app stays up). The rollout takes a plaintext backup outside data/ and deletes it only after media-check --compare passes. |
| T-4qu-08 | Information disclosure | GCM nonce reuse | low | accept | A random 96-bit nonce per 64 KiB chunk. The deployment encrypts far fewer than the 2^32 chunks per key where random-nonce collisions start to matter (63 MB is about 1000 chunks). |
| T-4qu-09 | Elevation of privilege | /media path building | low | accept | Unchanged: paths are built by the server from a validated 22-character id and a fixed variant map, so no client string reaches the filesystem. |
| T-4qu-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed. Only node:crypto, fs and stream are used. Every task's verify ends with `git diff --quiet HEAD -- package-lock.json`. |
