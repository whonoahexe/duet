<objective>
Add photo cropping and round profile photos. The plan has three parts: (1) a single hand-written crop screen, used with a fixed circle frame for profile photos and with Free / Square per photo in the send preview; (2) the server applies the crop rect the phone sends to the original before any variant is made; (3) an encrypted circular PNG "avatar-round" variant that the service worker uses as the notification icon, and every in-app profile photo renders as a circle.

Locked decisions (from .planning/notes/2026-10-21-crop-images-and-profile-photos.md and .planning/notes/2026-10-21-round-profile-photos.md). They are cited as N-xx in the tasks:
- N-01: Images only. No video trimming, no rotate.
- N-02: One hand-written cropper: pointer events for drag and pinch, a crop box with a dimmed overlay, and preset tokens and components for the buttons and toggle. No react-easy-crop and no other crop library.
- N-03: Profile photo: after choosing a photo, a fixed circle frame, drag and pinch to position, then Save. This replaces the automatic centre crop.
- N-04: Sending: a Crop button on each image in the send preview drawer (each image of an album is cropped separately), with Free and Square aspect options. Camera captures go through the same preview flow.
- N-05: The phone only picks the rectangle. It uploads the full-quality original plus the crop rect (normalised 0..1, relative to the EXIF-rotated image). The server applies it with sharp (rotate() first, then extract) before making thumbnails and variants. There is no canvas re-encode of the upload, and iPhone HEIC keeps going through the existing server path. The stored original is the cropped image. The rect is validated server-side with zod (0..1 bounds).
- N-06: Media is encrypted at rest. Every new stored file goes through the existing encryption path (encryptFile into media/<id>, with plaintext only in media/work scratch dirs).
- N-07: The server adds an "avatar-round" variant: the same photo masked to a circle with transparent corners, saved as PNG, encrypted like the other avatar files, and added to the /media route table. Existing photos get it lazily on first request. The service worker uses it as the notification icon (this only shows on the Pixel; iOS always shows the app icon).
- N-08: Round everywhere: chat header, incoming-call and in-call screens, top of the media gallery, profile photo drawer. Check every place that renders the photo without the preset Avatar (the call-screen image) and make it a circle.

Claude's discretion (choices made here):
- The crop rect travels in the complete request body (CompleteUploadBody). No DB column and no migration. complete() applies the crop before the row becomes "processing", so a job re-queued after a crash can never crop twice.
- The server re-encodes the cropped original once: JPEG quality 95 with 4:4:4 chroma, or PNG when the source has alpha. The client never re-encodes the upload.
- Both uses share one gesture model. For the profile, the "fixed circle frame" means the frame shape is a fixed, 1:1-locked circle that you move by dragging and size by pinching or with the corner handles.
- A small canvas preview of the crop (JPEG, long edge at most 1280) is used only for display in the preview drawer and in the sending bubble until the server copy is ready.
- avatar-round is 192 px, made from avatar-lg.webp (or from the same source as the other crops when a photo is set).
