# Phase 261022-m25 Plan 01: Crop and round profile photos Summary

The phone now picks a crop rectangle and uploads the untouched original. The server checks the rect with a strict zod schema and applies it with sharp (rotate() then extract) before any variant exists, so the encrypted stored original and every variant show the crop. Profile photos are framed in a hand-written circle cropper. Every drawable photo in the send preview can be cropped Free or Square. A new encrypted 192 px circular `avatar-round` PNG is the Android notification icon.

## What was built

- **shared/src/crop.ts**: `CropRect` (strictObject, 0..1, min side 0.01, x+w and y+h at most 1+1e-6), `cropToPixels`, `fullCrop`, `centredSquare`, `squareAround`, `moveCrop`, `resizeCrop`, `scaleCrop`, `CropBounds`, `CropCorner`. `CompleteUploadBody` is in shared/src/media.ts.
- **Server crop**: `withSharpSource` (the HEIC heif-convert step, now shared) and `cropImage` in image.ts. The complete route parses the body before any status branch. A bad rect, an extra key or a crop on a non-image gets 400 invalid_body. An undecodable image sent with a crop gets 422 unsupported_media and a failed row. `upload_completed` logs `cropped: true|false`.
- **avatar-round**: `writeRoundAvatar` (cover/centre 192 square, ensureAlpha, SVG circle with dest-in, PNG). `processAvatar` writes it, and `AVATAR_FILES` encrypts it. `ensureRoundAvatar` makes it on first request with one job per attachment, a scratch dir in media/work and an encrypted result. `/media/:id/avatar-round` is in the VARIANTS table, and a failure is logged as `avatar_round_failed` and answered with a no-store 404.
- **Cropper**: a full-screen preset Dialog (`FULL_SCREEN_DIALOG`) with a contain-fitted image, a dimmed outside (box-shadow in the background token at 60 %, clipped to the image), a 2 px foreground ring, four 40 px corner handles, and pointer-captured gestures (move / resize / pinch, with a pinch falling back to a move when one finger lifts). Every handler calls stopPropagation. It is rendered inside each parent DrawerContent so the drawer treats it as a nested popup.
- **PiP**: the swapped PiP peer photo is a round `PersonAvatar`. call-screen.tsx no longer has a raw `<img>`. The header, CallIdentity, gallery top and profile drawer were already PersonAvatar (rounded-full), confirmed by grep.

## Deviations from Plan

None in behaviour. Small implementation choices inside the plan's latitude:
- The preview drawer keeps its File array as render-time derived state, instead of `useMemo` over `items`. Otherwise every crop (which replaces the items array) would rebuild and revoke all object URLs and remount the strip tiles. Guarded index reads (`items[i]?.`) cover the discarded render pass.
- In CropDialog, Save may return a promise, so the button shows a spinner while the preview drawer builds the cropped preview.
- The crop smoke scenario also checks that the frame becomes square after "Square" and that dragging actually moved it.
